# Магазины, подпись и предупреждения систем

Это не юридическая консультация. Требования магазинов — договоры площадок, они меняются чаще законов. Дата памятки: 20 ноября 2026. Как подписана сегодняшняя сборка 0.1.1, уже написано в [справочнике](../GUIDE.md#desktop): macOS подписывается ad-hoc (`signingIdentity: "-"` в `desktop/src-tauri/tauri.conf.json`), Windows SmartScreen показывает неизвестного издателя, обновления подписываются minisign отдельно от подписи операционной системы.

Идентификатор пакета — `com.bot2217.ulei`, имя продукта — «Улей», бинарник — `ulei`. Цели упаковки сейчас: NSIS, MSI, DMG, AppImage, deb.

Подпись обновления minisign и подпись для Windows или Apple — разные ключи. Оба нужны, если обновление должно и ставиться молча, и не пугать систему. Секреты `TAURI_SIGNING_*` уже описаны в справочнике. Рядом с ними справочник оставляет место под сертификат Authenticode и Apple Developer ID. Эти секреты в репозиторий не кладут.

## Windows

SmartScreen оценивает репутацию файла и издателя. Обзор: [Microsoft Defender SmartScreen](https://learn.microsoft.com/en-us/windows/security/threat-protection/microsoft-defender-smartscreen/microsoft-defender-smartscreen-overview). Подпись Authenticode с отметкой времени описана в [документации по подписи кода](https://learn.microsoft.com/en-us/windows/win32/seccrypto/time-stamping-authenticode-signatures). Отметка времени нужна, чтобы подпись жила после истечения сертификата.

Сертификат покупается у доверенного удостоверяющего центра либо оформляется через [Azure Trusted Signing](https://learn.microsoft.com/en-us/azure/trusted-signing/overview). Репутация SmartScreen набирается на подписанных файлах, сама покупка сертификата не обещает, что предупреждение исчезнет в первый день. Пока предупреждение есть, текст в README остаётся: «Подробнее», затем «Выполнить в любом случае».

Публичный релиз на GitHub без сертификата уже возможен и идёт. Релиз «без неизвестного издателя» ждёт сертификата. Магазин Microsoft ждёт его обязательно.

Microsoft Store: [публикация приложений](https://learn.microsoft.com/windows/apps/publish/). Для витрины нужны пакет (обычно MSIX), возрастная анкета IARC, ссылка на политику конфиденциальности, ссылка на поддержку. Анкета шифрования — см. [EXPORT.md](EXPORT.md).

Песочница магазина плохо стыкуется с тем, что «Улей» делает сейчас: произвольная папка проекта, дочерние процессы shell, скачивание Ollama, локальный порт. Полноценный `runFullTrust` и широкий доступ к диску магазин рассматривает отдельно и может отклонить. Канал, который совпадает с продуктом на фазе 1, — подписанный NSIS/MSI с GitHub, не витрина Store. В Store идти после отдельного прохода по возможностям пакета, а не вместе с первым сертификатом.

## macOS

Ad-hoc подпись Gatekeeper не убеждает. Система может сказать, что «Улей.app» повреждено. Временный обход для пользователя уже написан в README: `xattr -cr` или правый клик → «Открыть». Для широкой аудитории это плохой постоянный путь.

Нужны сертификат Developer ID Application, включённый hardened runtime (файл entitlements уже подключён в конфиге Tauri), нотаризация и прикрепление билета. Порядок нотаризации: [Notarizing macOS software before distribution](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution). Программа Developer ID: [developer.apple.com/developer-id](https://developer.apple.com/developer-id/).

Сайдкар Python подписывается тем же идентичным разработчиком, что и оболочка. Иначе нотаризация падает на вложенном бинарнике. Текущий ad-hoc как раз подписывает и приложение, и сайдкар, но идентичностью `-`, не Developer ID.

Mac App Store — другой договор и другая песочница. Правила ревью: [App Store Review Guidelines](https://developer.apple.com/app-store/review/guidelines/). Пункт 2.5.2 требует, чтобы приложение было самодостаточным и не скачивало исполняемый код. Установщик Ollama, подкачка весов, которые затем исполняются, и shell в папке пользователя с высокой вероятностью не проходят это ревью. Канал macOS для текущего продукта — Developer ID и нотаризация, прямая загрузка DMG. Mac App Store не обещать в интерфейсе.

Аккаунт Apple Developer платный. Зачисление автора из России площадка может не пройти по собственным правилам и санкционному скринингу. Обход через чужой аккаунт сюда не входит. Если аккаунт недоступен, честный путь — оставить в README предупреждение Gatekeeper и не изображать нотаризацию.

## Linux

AppImage и deb с GitHub совпадают с тем, как программа устроена: она пишет в выбранную папку и запускает процессы.

Flathub: [требования к приложениям](https://docs.flathub.org/docs/for-app-authors/requirements). Сборка идёт без сети, зависимости перечислены в манифесте, исходники основного приложения собираются на инфраструктуре Flathub. Скачивание Ollama во время работы и зависимость от демона на хосте в эту модель не укладываются. Песочница Flatpak также ограничивает произвольную папку и shell. `extra-data` существует как редкое исключение и не стоит планировать на него установщик модели. Flathub реалистичен только если появится сборка, которая не скачивает бинарники мимо манифеста и ходит в файлы через портал. До этого Flathub не является каналом релиза.

Snap: правила витрины на [snapcraft.io/docs](https://snapcraft.io/docs). Строгое заключение даёт те же ограничения песочницы. Классическое заключение выдают отдельно и для агента с shell его могут не дать. Пока канал Linux — AppImage и deb.

Подпись пакетов: deb можно подписывать ключом репозитория, когда появится свой apt-репозиторий. Для одиночного файла на GitHub пользователи сверяют тег и, при желании, контрольную сумму в тексте релиза. Отдельного «SmartScreen для Linux» нет, поэтому подпись здесь про целостность, а не про диалог системы.

## Что обязательно, а что нет

| Шаг | GitHub-релиз | Магазин |
| --- | --- | --- |
| Исходники AGPL по тегу, LICENSE в комплекте | да | да |
| Политика конфиденциальности по постоянной ссылке | желательно, см. чек-лист | да, площадка спрашивает URL |
| minisign обновлений | да, иначе свой же updater не примет файл | да, если updater остаётся |
| Authenticode и отметка времени | чтобы убрать неизвестного издателя | да |
| Apple Developer ID и нотаризация | чтобы убрать «приложение повреждено» | для прямой загрузки да; Mac App Store — отдельный сертификат и, вероятно, другой продукт |
| IARC / анкета возраста | нет | да |
| Обещание Flathub, Snap, Mac App Store, Microsoft Store в интерфейсе | не давать, пока канал не принят | только после прохождения ревью |

Секреты подписи живут в GitHub Actions, не в git. Публичный ключ minisign уже записан в `tauri.conf.json`, ему в репозитории и место.
